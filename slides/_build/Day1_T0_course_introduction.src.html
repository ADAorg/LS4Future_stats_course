Why this course
Press run a few times. The true difference in the full trial is about 5 mm, yet small studies flip between "significant" and "not significant", and the estimated difference jumps around. Then add 100 studies: only a minority are significant, although the effect is real. Everything in Day 1 explains this slide: sampling variability, confidence intervals, p-values, power. The rest of the course builds on it.

Learning objectives
Eight objectives, roughly three per day. The emphasis is on interpretation and design decisions, not on memorising formulas or writing code. You will not leave as programmers; you will leave able to read an analysis critically, choose a sensible approach, and ask the right questions of a statistician or an AI.

Programme
The order is deliberate: uncertainty first, then models, then survival (which is a regression model for time with censoring), then design, which ties everything together. The final project on Day 3 uses a dataset you will have met on Days 1 and 2.

How the course works · Google Colab
Colab runs Python in the browser: nothing to install, a Google account is enough. If a cell errors, rerun the setup cell and run from the top. If something is badly broken: Runtime › Disconnect and delete runtime, then start again; the notebooks are built so each one runs independently. Many notebooks let you switch dataset from a dropdown, and some accept your own CSV.

Two AI roles: keep them apart.

🧮 GEMINI IN COLAB = CALCULATOR

Lives inside the notebook. Use it to write, change, fix or explain code, including new simulations.

"Add a second curve for α = 0.01 to this plot."
"This cell gives an error. Explain it and fix it."

Check: does the new output make sense, and did it change only what you asked?

🎓 CLAUDE / CHATGPT = TUTOR

In another browser tab. Use it to explain ideas, quiz you, and critique your own analysis.

"Explain a confidence interval with a lab analogy, then ask me 3 questions, one at a time."
"Here is my design: […]. What is the experimental unit? Ask me questions first."

Check: ask for the reasoning, and verify one claim yourself in the notebook.

Give it the whole design. AI answers the question you ask: if you call paired data "two groups" or forget to mention censoring, you get a correct answer to the wrong question. · Never paste identifiable patient data into a public chatbot.

How the course works · AI as a learning partner
Mixing the roles is the usual trap: asking the code assistant to interpret results, or pasting code into a chatbot and running whatever comes back. Gemini sees your notebook, so it's good at code that fits it. The chatbot is better at explaining, questioning and critiquing. Both are confident when they're wrong, which is why each slide says "check". Day 1's choosing-a-test cards show the failure that remains common: the AI answers exactly the question you typed.
